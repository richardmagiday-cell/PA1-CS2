Sorted Array Case:
For the sorted array case, my algorithm uses the two-pointer technique implemented in the getCandidatePair function. I place one pointer at the leftmost index (left = 0) and one at the rightmost index (right = n - 1) of the already-sorted array, then move them inward based on the current sum. If the sum of A[left] + A[right] equals the target, we found the pair. If the sum is less than the target, we increment left to increase the sum. If the sum is greater than the target, we decrement right to decrease the sum. Each iteration of the while loop moves at least one pointer by one step, so the two pointers together traverse at most n steps before they meet. No nested loops or sorting is needed because the array is already sorted. Therefore, the runtime of this approach is O(n).

Unsorted Array Case:
For the unsorted array case, my algorithm uses a HashSet to achieve O(n) runtime in the findPairUnsorted function. I iterate through the array once. For each element A[i], I compute the complement needed: need = target - A[i]. I then check whether that complement is already in the HashSet (a lookup that costs O(1) on average). If it is, the pair (A[i], need) sums to the target and we return immediately. If not, I insert A[i] into the HashSet (also O(1) on average) and continue to the next element. Since we do exactly one pass through the n elements and each HashSet insert and lookup is O(1), the total runtime is O(n).
